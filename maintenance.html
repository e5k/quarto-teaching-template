Maintenance

Two-way Git updates, dependency inventories, troubleshooting and a changelog.

1 Two-way updates with Git

Local repository connections · Native Git commands

Each course contains ordinary local template files. The repositories are independent: a normal clone contains the files needed by that course. There is no custom template manager, _teaching/ directory, lock manifest, Git subtree or Git submodule in the current setup.

Use feature commits to transfer improvements. A feature commit contains only the reusable change and all files required to implement it. Git fetch reads another repository’s commits; cherry-pick applies one selected commit to the current branch. It creates a new commit, rather than continuously linking files.

1.2 Commit a reusable improvement

Make a change in the template or a course. Stage exact paths, then inspect the staged diff:

# Example: a change to the profile-icons feature
git add -- slides/_template.yml slides/_extensions/course/author-links/
git diff --cached
git commit -m "Template: improve author profile icons"
git rev-parse HEAD

Use the paths appropriate to the actual feature. If a file contains both shared and course-specific changes, git add -p -- path/to/file lets you stage selected hunks. Check git diff --cached for all staged content: git commit without path arguments includes everything staged, including any earlier work.

Do not include course titles, chapter edits, bibliography entries, datasets or personal URLs in the shared feature commit. Commit those separately in the course repository. New plugins typically need a YAML declaration and a complete extension directory; adding only a configuration line leaves an incomplete feature.

1.3 Template to a course

Run in the destination course:

git fetch template
git log --oneline teaching-template-baseline-2026-11-04..template/main
git show TEMPLATE_COMMIT
git cherry-pick -x TEMPLATE_COMMIT

Replace TEMPLATE_COMMIT with a real feature hash from the log. git show displays the whole commit, not just one file; review it before applying. The baseline range omits the initial template commit but does not guarantee every later commit is shareable. Documentation and starter-content commits must also be reviewed for relevance.

-x records the source hash in the new commit message. If a feature spans several commits, inspect and import each in dependency order. Do not cherry-pick a whole branch or broad range just to obtain one feature.

1.4 Course to template and onward

First commit the reusable feature in the source course. Then run in the central template:

git fetch outils-info-2
git log --oneline outils-info-2/main
git show COURSE_COMMIT
git cherry-pick -x COURSE_COMMIT
git rev-parse HEAD

Use analyse-geospatiale in place of outils-info-2 for that source. Take the new template hash printed by the final command and import it into the other course with the template-to-course procedure.

The source course already has the feature; do not send the same change back to it. Cherry-picked copies have different hashes, so hash inequality alone does not prove a feature is missing. Read the -x provenance and inspect the content. Keep the template commit message clear enough to recognise the feature later.

Do not git pull or merge an entire course branch into the template: the branch also contains local lessons and configuration. These independent repositories do not have a shared course-history model.

1.5 Add another course or move to GitHub

After creating a new course repository and committing its matching shared files, connect it locally:

# In the course; replace the path for your computer
git remote add template /path/to/_quarto-course-template
git fetch template

# In the template; replace both placeholders
git remote add my-course /path/to/my-course
git fetch my-course

For GitHub-backed collaboration, create each repository and push its own branch intentionally. Then change the template and course-source URLs to those verified repository URLs with git remote set-url. Merely changing a URL does not create the remote repository or publish any files. Keep each course’s own origin distinct from its template remote. Avoid inventing or copying an unverified URL.

2 Local changes and conflicts

Prefer a clean working tree before importing a feature. Commit unrelated course work on its own first. If you need to set it aside temporarily:

git stash push -u -m "Before template update"
git fetch template
git cherry-pick -x TEMPLATE_COMMIT
git stash pop

-u includes untracked files, but not ignored files. Inspect what is untracked before stashing: an untracked planning dataset may be large. A stash is local storage, not a remote backup. Restoring it can produce a second set of conflicts even after the cherry-pick succeeds.

If Git pauses a cherry-pick:

git status
# Edit each conflicting file and remove conflict markers.
git add -- path/to/resolved-file
git cherry-pick --continue

To abandon the in-progress import, use git cherry-pick --abort. To undo a completed, published import, consider a new git revert commit after inspecting its scope; do not rewrite shared history casually. An empty cherry-pick often means the feature is already present—inspect before choosing git cherry-pick --skip.

Git does not understand which YAML values are “generic”. The YAML split and focused commits provide that boundary. If a conflict mixes a course bibliography path with a shared plugin setting, keep the path local and move the plugin change into the appropriate _template.yml.

5 Verify an update

After an import, review git show --stat HEAD and the changed lines. Validate the outputs affected by the feature:

Change Useful verification
Profiles or callouts Render the same chapter under both profiles; inspect written answers, code output, numbering and collapsed answers.
Exercises Try a correct, incorrect and blank response; check grouping and solution toggles.
Notebook conversion Open the resulting notebook; confirm code cells, outputs, Markdown wrappers and answer-source policy.
Slide layout or animation Present a representative deck, step through every affected fragment and inspect different image heights.
Bibliography or portability Refresh the copy, render citations, then copy slides/ elsewhere and preview it there.
PDF export Run the normal Decktape workflow and inspect pages, including fragment captures.
Documentation From doc/, run quarto render; verify links, search, examples and narrow-screen layout.

A successful --no-execute render checks the available layout and source processing; it does not validate analytical code. A successful browser demonstration does not establish PDF compatibility.

6 Troubleshooting

Symptom Check and correction
Specified Reveal plugin directory 'animate' does not exist Confirm you copied slides/_extensions/fradav/animate/ and are using the slide project’s YAML. The whole directory is needed.
Deck renders as an ordinary HTML page Check that its filename matches slides/_quarto.yml → project.render; then confirm the separate slide project is loaded.
clean-revealjs is not found Restore slides/_extensions/grantmcdermott/clean/ and its manifest.
Question blocks look like ordinary text Source must use .question / .answer; load the custom-callout filter and definitions.
Missing question number or duplicate header Use exr- / sol- IDs; keep the header integration script and CSS together. Matching suffixes pair answers with questions.
Answers appear in a question render Inspect document answers overrides and confirm every written answer is wrapped conditionally.
Code runs although its answer is hidden Conditional visibility does not disable execution. Review cell eval options.
Notebook still contains answers Expected with the current converter; it retains source and does not apply profile filtering.
Number 01 notebook will not build The current discovery code always excludes 01. Change it deliberately for a course with a first-class practical.
Nothing rendered for a slide selector The script only warns on missing slide names. Check the actual files and use a matching selector.
Missing references in an extracted deck Run the slide script before extraction; check slides/assets/ and the local bibliography path.
Profile icons absent Check author-links, global and per-service enabled switches, the order list, a valid HTTP(S) URL, first-author markup, filter registration and the icon stylesheet.
Repeated-title switch has no effect Re-render the deck, and transfer both course/slide-options and the updated after-body script. An old HTML file does not read new YAML.
SVG animation fails from a local file Serve the deck over HTTP; verify SVG paths, IDs, the filter and plugin.
Lightbox does not open .lightbox is a marker; enable lightbox: true locally as well.
Layout overflows after an image offset Relative offsets do not alter reserved layout space. Reduce media size or use normal columns before offsets.
decktape or gs cannot be found Install the required tool or use --no-pdf; use --no-compress when only Ghostscript is missing.
Unexpected template content imported Inspect the chosen commit. Cherry-pick copies the entire commit; use focused feature commits and abort unresolved imports if needed.

7 Maintain this manual

The documentation is an independent Quarto website under doc/ in the template repository. Its render list names exactly four guide pages and the index. The manual loads a local copy of the course’s shared _template.yml, including its actual assets/custom.css and assets/dark.scss, profile files, notebook-link filter, CSL and after-body scripts. Supporting assets also include the custom-callout extension and exercise files required by live examples. These are local snapshots: refresh the shared YAML and its companion files together when the source theme changes. Keep assets/docs.css limited to documentation layout so that it does not replace the course palette or typography. Directory-level _metadata.yml keeps the documentation language and table-of-contents label in English and disables external comments after the shared project metadata has been loaded.

The embedded slide deck is a pre-rendered demonstration made with the real slide project. Rebuild it when the slide theme changes, keeping the HTML and its dependency directory together under doc/assets/demos/slides/. Its downloadable source is supplied there as demo.qmd.txt to preserve the five-page QMD structure. To rebuild, copy that source into an isolated copy of the template’s slide project, rename it demo.qmd, include demo.qmd in that copy’s project.render list, add the supplied SVG, then render with Quarto. The documentation’s ordinary render does not rebuild the embedded deck.

8 Documentation publication

The public website is https://e5k.github.io/quarto-teaching-template/. Sources live on main; only doc/ is rendered by .github/workflows/publish-docs.yml. A push affecting doc/** or that workflow starts a build with Quarto 1.8.27. The action updates gh-pages and explicitly deploys the rendered doc/_site/ artifact using GitHub Pages. It can also be run manually from the repository’s Actions tab.

GitHub Pages uses the GitHub Actions publishing method. The gh-pages branch is maintained as the rendered publication output; doc/_site/ stays ignored on main. The course starter book at the repository root is not published as this website.

For a manual local publication, run quarto render doc followed by quarto publish gh-pages doc --no-render --no-browser from the repository root. The automated workflow is preferred for regular updates because it also performs the explicit Pages deployment.
