1 Book structure and chapter numbering

Native Quarto book structure · Existing teaching convention

A teaching block is a part; a class or substantial topic inside it is a chapter. In the current HTML book, a part-introduction page is unnumbered and does not consume a chapter number. The chapters within it are numbered in reading order. Chapter numbers continue across parts.

This behaviour already works with the shared template. It is controlled by the course’s book.chapters structure in root _quarto.yml; it requires no new filter, filename parser or template option. The generic starter uses a simple chapter list, while Outils informatique II already uses file-backed parts.

1.1 Page roles

Role Meaning Current HTML numbering
Welcome page Overall course context and practical information Unnumbered when explicitly configured that way, or when used as a part landing page
Part with an introduction file A block overview, objectives, prerequisites and links to its classes No chapter number; its subsections are also unnumbered in the verified example
Part with a text label only A navigation grouping without its own introduction page A group title, not a chapter
Chapter A class, practical or substantial topic listed under chapters Continuous numbers, 1, 2, 3…
Explicitly unnumbered chapter Optional notes or other prefatory material No chapter number and no gap in the numbered sequence
Appendix Supporting material under book.appendices Separate letters, A, B…
References A bibliography page Unnumbered when its main heading is explicitly marked .unnumbered

The same source file can play a different role in a different book. Its filename does not permanently declare it to be a part, a chapter or a particular chapter number. Keep that role in each course’s book configuration.

1.2 A complete two-block example

book:
  chapters:
    - index.qmd
    - part: course/exploring-introduction.qmd
      chapters:
        - course/reading-data.qmd
        - course/describing-data.qmd
    - part: course/inference-introduction.qmd
      chapters:
        - course/sampling.qmd
        - course/comparing-groups.qmd
  appendices:
    - appendices/reference-sheet.qmd
    - appendices/references.qmd

Create every listed file. With the welcome and references headings marked unnumbered, the reading structure is:

Welcome                         unnumbered
Exploring data                  part introduction, unnumbered
  1 Reading data
  2 Describing data
Statistical inference           part introduction, unnumbered
  3 Sampling
  4 Comparing groups
Appendix A — Reference sheet
References                      unnumbered

part: points to the block introduction. Its nested chapters: list supplies the classes. The second part does not reset chapter numbering. Listing a new part or moving a chapter does not require renaming a source file. The top-level book.appendices list is separate from the main chapter sequence.

1.3 Write a block introduction

For the file referenced by part: course/exploring-introduction.qmd, use a normal title and content:

---
title: "Exploring data"
---

## Learning objectives

By the end of this block, students can inspect and describe a dataset.

## Classes in this block

- [Reading data](reading-data.qmd)
- [Describing data](describing-data.qmd)

The part role supplies the unnumbered block-introduction behaviour. _intro in a filename has no such effect by itself. Do not also add the same file as an ordinary chapter to obtain an introduction page; the file-valued part already provides it.

If the block only needs a navigation label, use a string instead of a file:

- part: "Statistical inference"
  chapters:
    - course/sampling.qmd
    - course/comparing-groups.qmd

A string label does not create a QMD landing page in which to place objectives or other content.

1.4 Outils informatique II uses this structure already

The current course configuration includes the following block:

- part: course/semaine_03-05_intro.qmd
  chapters:
    - course/semaine_03.qmd
    - course/semaine_04.qmd
    - course/semaine_05.qmd

The part page is titled “Semaines 3–5 — Statistiques univariées”. It has no generated chapter number. Its first class is chapter 3, “Du catalogue à l’échantillon analysable”, because two numbered chapters precede it elsewhere in the book. The “3–5” in the part’s title is manually written teaching-schedule information; it is not the part’s generated number.

The course also uses part: index.qmd as its home/overview entry. Its local home page disables section numbering explicitly. The shared assets/book-index-link.html helper makes that first part label clickable when it finds the expected sidebar structure. A generic book can instead list an unnumbered index.qmd directly; the helper is not required for every book layout.

1.5 Chapter numbers, section numbers and sidebar display

The shared _template.yml enables format.html.number-sections: true. For a normal chapter:

# Reading data {#sec-reading-data}

## Inspect the observations

### Check the units

The chapter’s first heading receives its chapter number; the following headings receive hierarchical section numbers. With this file as chapter 1, the first subsection is 1.1. Use the title in YAML instead of the first heading if preferred, but do not manually prefix a title with its generated number.

number-depth controls how deeply headings are numbered. toc-depth controls how deeply they appear in the table of contents. These are separate settings. A per-page number-sections override can affect that page, so inspect its front matter when numbering differs from the shared default.

The left sidebar is another independent layer: assets/custom.css hides .chapter-number spans there. Chapters remain numbered in page titles, cross-references and section numbering even though the sidebar omits their numeric prefixes. Removing a visible sidebar prefix is not the same as declaring a chapter unnumbered.

The presentation setting repeated-slide-titles only controls counters such as “Terrain (1/3)” in slides. It does not affect any book numbers.

1.6 Unnumbered supporting pages and references

For an ordinary page in a chapters list that should not count as a chapter:

# Optional notes {.unnumbered}

In the verified example, an optional unnumbered page between chapters 3 and 4 did not consume a number. This is appropriate for prefatory or supporting content; it is not necessary on an introduction that already serves as part:.

For a bibliography page:

# References {.unnumbered}

::: {#refs}
:::

Outils informatique II already uses this form in appendices/references.qmd. The page therefore does not receive an appendix letter. Other numbered entries under book.appendices use letters rather than continuing the main chapter numbers. Depending on the output language, the generated title prefix can be “Appendix” or “Annexe”.

1.7 Stable cross-references and ordinary links

Give reusable numbered sections stable semantic identifiers, for example #sec-reading-data, rather than identifiers such as #sec-chapter-03. Refer to the former with @sec-reading-data; its displayed number is resolved from the current book order.

Use source links such as [Block overview](exploring-introduction.qmd) for unnumbered introductions. Quarto resolves a source QMD link to its rendered page. Keep the path relative to the file containing the link, and retain any explicit anchor when linking to a subsection.

Chapter-based cross-reference numbering has limits in unnumbered pages. Keep figures, tables and exercises that need numbered chapter-based references in numbered chapters, and use ordinary links for prefatory content. See the official book structure and book cross-reference references for format-specific details.

1.8 Filenames, sessions and book order are separate

Native book rendering accepts descriptive filenames and optional subdirectories when they are explicitly listed in the book configuration. Directories do not automatically create parts; file numbers do not control chapter numbers. Moving a chapter to another part changes its book position without changing its source filename.

A teaching session is a separate scheduling concept. One session can use several chapters, and one chapter can span several sessions. Slides and notebooks can be authored accordingly, but the current template does not implement a metadata mapping system for arbitrary chapter-to-slide or chapter-to-notebook associations.

The existing notebook automation still requires numbered, top-level filenames and excludes number 01. Therefore the book is already structurally modular, while the notebook pipeline retains the conventions documented under filenames and script constraints. Do not rename an entire existing course to descriptive filenames and expect that pipeline to discover them automatically.

1.9 What is and is not changing

No runtime template modification is required for unnumbered part introductions and numbered chapters. The existing native structure is the supported approach. Keep each course’s hierarchy in its local _quarto.yml; copying the generic starter’s chapter list into a course would discard its teaching-block organisation.

This convention has been verified for the current HTML book. Other formats may display parts differently, so inspect those outputs separately before promising identical part presentation. A future change to support arbitrary notebook names, nested discovery or explicit material associations would be a separate build-script enhancement, not a requirement for the numbering described here.

2 Profiles

Native profiles · Local settings

The book is one project with two mutually exclusive profiles, answer and question. The profile group is declared in root _template.yml; profile values live in _quarto-answer.yml and _quarto-question.yml.

Setting Answer profile Question profile
answers true false
execute.echo true true
execute.output true false
Written answer content Visible when wrapped with when-meta="answers" Removed from rendered output by the same condition
Notebook and other links Displayed; .ipynb links receive download Entire .quarto-other-links region hidden by CSS 
quarto render --profile answer
quarto render --profile question

Root _template.yml defaults to answers: true. Both builds normally use the same _book/ directory, so the most recent render replaces the corresponding output. Archive or copy a completed build if you need to retain both variants.

2.1 Written content and execution are separate

Wrap every written answer that should disappear from the question version:

::: {.content-visible when-meta="answers"}
The pattern supports an association, but does not establish causation.
:::

Hiding output does not hide ordinary Markdown or Python source. Conditional content also does not prevent execution of wrapped cells. For a specific cell, use native execution options deliberately:

```{python}
#| echo: false
#| output: true
print("A displayed result without the source code")
```

echo controls source display, output controls results and eval controls whether the cell runs. An explicit cell option can override project defaults. Do not use visibility rules as a substitute for execution control.

2.2 Check document overrides

A chapter containing the following metadata can behave differently from its selected profile:

answers: true
execute:
  output: false

This combination is present in some existing course material: written answers can remain visible while cell results stay hidden. Remove overrides when you want profile values to govern the page. Render the actual chapter under both profiles and inspect the result; do not infer visibility only from the command name.

3 Questions and answers

Extension: custom-callout · Native cross-references · Local header integration

The custom-callout extension reads the definitions in _template.yml. Use .question or .answer in the source. The extension converts these into rendered .callout-question and .callout-answer elements. Writing .callout-question directly bypasses this class-to-definition conversion.

Type Configured label Icon Colour Default collapse
.question Question fa-circle-question #6f42c1 No
.answer Réponse fa-circle-check #2e8b57 Yes in HTML

3.1 Number a question and its answer

::: {#exr-compare .question title="Compare the two distributions"}
Which feature changes when the extreme value is removed?
:::

:::: {.content-visible when-meta="answers"}
::: {#sol-compare .answer title="Réponse"}
Return to @exr-compare.

The median changes less than the mean.
:::
::::

exr- activates native exercise numbering. sol- activates a solution; the matching suffix compare lets the local header script associate the answer with the question. IDs must be unique throughout the book. Use stable descriptive IDs so links survive title edits. Put the whole answer, including its title and source cells, inside the conditional wrapper. The outer wrapper uses four colons to make nesting clear.

Rendered example, with answers visible in this manual:

Question 1  

QuestionCompare the two distributions

Which summary is usually less sensitive to one extreme value: the mean or the median?

Solution 1.

AnswerRéponse

The median is usually less sensitive. Return to question 1.

3.2 Titles and header numbering

Supply title="..." on the source div, or use a first heading inside it. If both are present, the title attribute wins. The extension also accepts icon, appearance and collapse div attributes; the global settings supply defaults.

The local assets/theme-toggle.html script finds native question/solution labels and moves them into the coloured header. An answer with the matching suffix receives the corresponding question number, with “Question” replaced by “Réponse”. It removes a redundant answer title when that title is simply “Réponse” or “Answer”. Root assets/custom.css suppresses the original separate numbering line.

Transfer all three layers together: the custom-callout extension, the custom-callout definitions in _template.yml, and the CSS/JS header integration. A styled block without an exr- ID is a callout, but is not a numbered exercise.

The book’s custom types are not configured in slides/_template.yml. To use them in slides, you would need to add their extension and definitions to the slide project; ordinary Quarto callouts already work there.

4 Interactive exercises

Third-party webexercises assets · Course Python integration

Root _template.yml loads assets/webex.css and includes assets/webex.js after the document. These files are derived from webexercises and run in the browser. Outils informatique II additionally uses pywebexercises.exercises to generate exercise HTML from Python. That Python package is a separate dependency, not bundled in the template.

The raw HTML interface below works without Python and describes the contract used by the included JavaScript.

4.1 Text and numeric responses

<label for="crs-answer">LV95 EPSG code</label>
<input id="crs-answer" class="webex-solveme" data-answer='["2056"]'>

data-answer must contain a valid JSON array. Matching is exact by default. Add .ignorecase for case-insensitive input or .nospaces to remove ordinary space characters before matching. The current .nospaces implementation removes spaces, not all whitespace.

<input aria-label="Rock type"
       class="webex-solveme ignorecase nospaces"
       data-answer='["basalt", "basalte"]'>
<input aria-label="Approximate result"
       class="webex-solveme" data-answer='[10]' data-tol="0.1">

Positive data-tol accepts a numeric difference strictly smaller than the tolerance. .regex interprets the joined answer strings as a JavaScript regular expression. Use anchored patterns such as ^basalt$ if a whole response must match. For routine exercises, prefer explicit accepted strings over regular expressions.

4.2 Dropdowns and radio buttons

<label for="unit-choice">Choose a projected coordinate unit</label>
<select id="unit-choice" class="webex-select">
  <option value="blank">Choose an answer</option>
  <option value="wrong">Degrees</option>
  <option value="answer">Metres</option>
</select>

<div class="webex-radiogroup" id="unit-radio">
  <label><input type="radio" name="unit-radio" value="wrong">Degrees</label>
  <label><input type="radio" name="unit-radio" value="answer">Metres</label>
</div>

The correct option must have the literal value answer; dropdown placeholders use blank. Give each radio group a unique, simple ID and use exactly that ID as the name of its inputs. Avoid spaces or punctuation in these IDs because the current script builds a CSS selector from them.

4.3 Check a group and reveal an explanation

<div class="webex-check webex-box">
  <label for="group-answer">LV95 EPSG code</label>
  <input id="group-answer" class="webex-solveme" data-answer='["2056"]'>
</div>

<div class="webex-solution">
  <button type="button">Explanation</button>
  <p>LV95 uses EPSG:2056.</p>
</div>

.webex-check adds a “Show Answers” / “Hide Answers” button and a correct-count indicator. It changes feedback visibility; it does not fill the correct responses into empty controls. .webex-solution requires a button directly inside the container; clicking it toggles the container’s open class.

These controls provide local feedback, not stored assessment results. The answer values are delivered to the browser in the HTML. Native book profiles do not automatically remove webex answer keys. The current JavaScript also resets response boxes when a page loads and assigns window.onload; another script that replaces that handler can stop exercise setup.

5 Notebook links and conversion

Local Lua filter and Python builder

Add the download link in a chapter’s YAML:

other-links:
  - text: Notebook Jupyter
    icon: file-earmark-code
    href: class_02.ipynb

The notebook sits beside its source chapter, so the link is relative to that page. The Lua filter scripts/notebook-links.lua inspects the effective answers metadata:

  • When it is true, JavaScript adds download to links in .quarto-other-links whose href ends exactly with .ipynb.
  • Otherwise, CSS hides all .quarto-other-links, including any unrelated links placed there. Links elsewhere in the page are unaffected.

The filter does not generate notebooks or prevent someone opening a known notebook URL. A query suffix such as .ipynb?download=1 does not match its current end-of-string selector.

python scripts/render_notebooks.py 2
python scripts/render_notebooks.py course/class_02.qmd

The script runs quarto convert, writes an IPYNB next to each chapter, then clears outputs, execution counts and cell metadata. It sets a generic Python 3 kernelspec. It removes #| cell-option lines, selected Quarto div wrappers, heading attributes, image attributes, pagebreak shortcodes and Font Awesome shortcodes.

Answer source remains in converted notebooks. The script does not evaluate when-meta="answers" or apply the question profile. It strips wrappers while retaining their content. Its wrapper-cleaning expression recognises exactly three-colon fences; longer nested fences can remain. Inspect a representative notebook before distribution, particularly chapters with nested answers and HTML exercises.

The book’s resources list must include course/*.ipynb if the generated notebooks should be copied into the published output. keep-ipynb: false concerns Quarto’s execution intermediates; it is separate from notebooks deliberately generated by this script.

6 Citations and references

Native Pandoc citations · Local Zotero convention

Keep each course’s Zotero export in root assets/. Choose its own filename: OI2.bib, geospatial.bib or another appropriate name. Set that path in root _quarto.yml; the shared _template.yml sets the CSL to assets/bulletin-of-volcanology.csl.

The interpretation follows previous work [@yourCitationKey].

@yourCitationKey provides the original method.

## References

::: {#refs}
:::

Use a real key from the bibliography. The #refs container chooses where references appear. A whole-book references appendix can be listed in book.appendices; the filename and chapter organisation belong to the course.

Do not manually edit Zotero-synchronised entries. Import new references into Zotero and refresh its export. The slide script copies root bibliography files into slides/assets/; see standalone slides.

7 Appearance and authoring helpers

Local CSS and JavaScript · Native HTML theming

The book uses Cosmo in light mode and Darkly plus assets/dark.scss in dark mode. Syntax highlighting is atom-one / dracula. Root assets/custom.css sets Source Sans Pro for text and Roboto Slab for headings, loaded from Google Fonts with local fallback fonts.

Helper or behaviour Usage Effect
.bg [key phrase]{.bg} Teal translucent marker effect, including wrapped lines. It is orange in slides.
.btn .btn-download Apply to a Markdown link Rounded orange-outline button; the download attribute is separate.
.nowrap-first-col Apply to a table or wrapping div Prevents wrapping in the first table column. Long content can overflow a narrow screen.
.reveal-embed Apply to an iframe Full-width 16:9 embedded deck; 4:3 on narrow screens.
Documentation icon links A link containing .fa-book or .fa-graduation-cap Compact raised icon beside a function name; not applied inside sup.
Table stripes Automatic on table.table rows Alternates odd rows using light/dark CSS variables.
Figure alignment Automatic Left-aligns ordinary Quarto figure images.

Live book highlight: a shared scientific question.

[Download data](data/samples.csv){.btn .btn-download download="samples.csv"}

The CSS styles the link; it does not provide the file. To add a Font Awesome icon, enable the bundled fontawesome shortcode extension in that page or project’s filters, then use:

[{{< fa download >}} Download data](data/samples.csv){.btn .btn-download}

The root starter’s shared filter list contains notebook-links.lua and custom-callout; it does not enable fontawesome globally. The installed extension folder alone does not activate its shortcode.

7.1 Code annotations and figures

Line numbers and hover annotations are enabled in the HTML book. Use native <1> comments and an immediately following annotation list. The local CSS moves the copy button away from annotations.

```{python}
values = [2, 4, 8]  # <1>
mean = sum(values) / len(values)  # <2>
```

1. The observations used in the calculation.
2. The arithmetic mean.

For Matplotlib figures, load the supplied style explicitly; copying the file does not activate it:

import matplotlib.pyplot as plt
plt.style.use("assets/plots.mplstyle")

With Quarto’s normal document-relative execution, use ../assets/plots.mplstyle from a chapter in course/. If the course sets a project execution directory, adjust the path accordingly. The style sets Roboto, teal labels and a #fafafa figure background; it does not automatically switch plot colours in book dark mode.

7.2 Navigation and small fixes

The template enables section numbering, page navigation, book search and a right-hand table of contents to depth 4. Sidebar chapter numbers are hidden visually; this does not disable section numbering elsewhere. assets/book-index-link.html turns the first sidebar part label into a home link when the book uses the matching first-part structure; it does nothing when that element is absent.

assets/theme-toggle.html also wraps Quarto’s colour toggle to restore the scroll position after a theme switch. The same file currently contains the question/answer header integration, so keep it when transferring either feature. Hypothesis comments are enabled under comments.hypothesis in shared YAML and depend on the external service.

For native behaviour beyond the local configuration, consult conditional content, code annotations and citations.
